# 使用手册生成器（User Manual Generator）

**一个系统 → 一份全量功能参考手册**：通过结构化工作流，将系统信息整理为一份覆盖全部功能模块的《使用手册》。手册的定位是**参考型文档**——用户遇到某个功能时来查"这个功能是什么、怎么用、有什么限制"，而不是教用户完成某项业务。

## 与《操作说明》的关键区别（生成前必读）

| 维度 | 使用手册（本 skill） | 操作说明（另见 operation-guide） |
|---|---|---|
| 定位 | 参考型（Reference），全量覆盖 | 任务型（Task-oriented），只讲主流程 |
| 组织方式 | 按**系统功能模块/菜单结构**组织 | 按**业务场景/操作流程**组织 |
| 读者状态 | 用户想知道"某个功能怎么用" | 操作者想知道"这件事该怎么做" |
| 内容粒度 | 每个功能：定义、入口、参数、步骤、结果、限制 | 每个流程：步骤、预期结果、风险、检查点 |
| 篇幅 | 长，允许详尽 | 短，只保留主链路，少解释 |

生成前先确认：用户要的是哪一份。若用户说"所有功能的详细介绍"→ 本 skill；若用户说"主流程、教操作者做事"→ 转用操作说明 skill。

## Quick Start

用户只需提供系统/产品信息（功能清单、界面说明、需求文档等，可以是零散材料），Agent 按以下工作流输出完整手册：

```
User: 帮我给这个 WMS 系统写一份使用手册（附功能清单/原型/需求说明）
Agent: [澄清关键信息 → 按功能模块逐个生成 → 输出完整手册 Markdown]
```

## SOP 工作流

### 阶段 0：信息收集与澄清

**目标**：确认手册覆盖范围和写作约束。

**步骤**：
1. 解析用户提供的材料：系统名称、功能模块清单、界面结构、目标读者。
2. 缺失信息时提问（最多 4 个关键问题），例如：
   - 系统的目标用户是谁？（业务人员 / 管理员 / 技术人员；新手还是熟练用户）
   - 交付形式？（Markdown / Word / 在线帮助中心）
   - 封面信息有哪些？（公司名称、**公司 Logo 图片**、产品版本号、编写日期）
   - 是否有界面截图可用？（无截图时用文字描述界面元素 + 占位说明）
3. 用户要求跳过时，采用默认假设：读者为初次使用该系统的业务人员；Markdown 输出；封面用占位符（`{公司名称}`、`{LOGO}`、`{YYYY年M月}`），不编造真实公司信息。

**输出**：手册元数据（系统名、版本、读者、模块清单），不超过 150 字。

---

### 阶段 1：骨架搭建

按以下固定骨架生成手册目录。**目录结构必须与系统菜单/功能模块层级一致**（搜索参考：企业文档规范中"目录结构按系统菜单层次构建"的实践），功能按主次顺序排列：

```
【封面页】（独立一页，无页眉页码，版式见"版式与排版规范"）
【目录页】（自动目录，含章节名与页码，无页眉或页眉从正文起）
《{系统名称} 使用手册》

1.  文档信息（版本号、修订记录表、编写/审核/日期）
2.  引言
    2.1 手册说明（本手册面向谁、怎么用这本手册）
    2.2 系统简介（产品定位与核心价值）
    2.3 运行环境（硬件/软件/浏览器/网络要求）
    2.4 术语与约定（术语表；界面元素、按钮、菜单的书写约定）
3.  快速上手
    3.1 登录与退出
    3.2 主界面布局介绍（导航栏、工作区、状态栏等）
    3.3 一个最小完整示例（带用户走通一个最简单的功能）
4.  功能详解（按模块分章，每个一级模块一章）
    4.{n} {模块名}
        4.{n}.1 模块概述（业务目标、主要流程、前置条件）
        4.{n}.2 {功能A}
        4.{n}.3 {功能B}
        ...
5.  常见问题（FAQ）
6.  附录
    6.1 快捷键一览
    6.2 错误代码/提示信息说明
    6.3 技术支持联系方式
```

**每个模块章（4.{n}）开头必须有"模块概述页"**：用 100–200 字说明该模块的业务目标、主要流程和适用角色，语言简洁清晰（行业规范明确要求每个模块需有概述页面）。

**通用性功能**（登录、查询、导入导出、打印、消息通知等跨模块功能）：单独归入"通用性功能"一章，避免在各模块重复描述。

---

### 阶段 2：功能详解写作（手册主体）

每个功能条目严格采用以下五段式结构：

```
#### {功能名称}（动宾结构命名，如"上报申购单"）

【功能说明】2-4 句话：这个功能做什么、解决什么问题、什么场景下使用。

【入口与前置条件】
- 入口路径：导航至「主菜单 → {模块} → {页面}」
- 所需权限/角色：
- 前置数据/状态条件：

【操作步骤】（编号列表 + 祈使句，一步一动作）
1. 点击「{按钮}」按钮。
2. 在「{字段}」输入框中填写 {内容说明}。
3. ...

【参数/字段说明】（表格）
| 字段 | 类型 | 必填 | 说明 | 默认值 |
|------|------|------|------|--------|

【输出与结果说明】执行后系统做什么、页面反馈是什么、数据流向哪里、结果如何确认。

【注意事项与限制】（无则省略）
- 操作限制（状态、条件、顺序约束）
- ⚠️ 风险警告：删除、覆盖、批量操作等不可逆操作必须突出提示
- 常见误操作及后果
```

**关键写作规则**：
- **完整性优先**：对照功能清单逐条覆盖，宁可详尽不可遗漏——用户买手册就是为了"全"。
- **每个操作步骤三要素**：操作位置（"导航至…页面"）+ 执行动作（"点击…按钮"）+ 预期结果（"系统将…"）。禁止出现"大概""可能"等模糊词，所有步骤必须基于真实可验证的系统行为。
- **术语首次出现括号标注**：如 `WMS（仓库管理系统）`。
- **界面元素书写统一**：菜单用「」、按钮用「」、字段用「」；同一对象全文只用一个名称。
- **图文规范**：有截图时每步配图，截图需有标注（红框/箭头）说明操作位置；无截图时在【操作步骤】中用文字精确描述界面元素的位置和形态。

---

### 阶段 2.5：版式与排版规范（生成 Word/PDF 时强制执行）

以正式交付的用户手册版式为基准（参考客户实际手册样例），排版要求如下：

**1. 封面（独立一页，无页眉、无页码）**

版式自上而下：
1. **文档标题**：`《{系统名称} V{X.X} 使用手册》`，页面中上部，字号最大（如小二/一号），加粗居中；版本号随标题同行或副标题行
2. **公司 Logo**：标题下方居中放置（用户提供 logo 文件；未提供时保留 `【此处插入公司 Logo】` 占位，不得编造）
3. **公司名称**：Logo 下方，居中，字号三号左右
4. **编写日期**：页面底部居中，`{YYYY年M月}`（只精确到月，参考样例格式）

封面之后依次为：目录页（含页码）→ 正文。

**2. 页眉（正文每页页眉）**

- 页眉内容：`{公司名称}` 或 `{系统名称} 使用手册`，可加 logo 小图；左右分栏样式（左侧 logo/公司名，右侧文档名）亦可
- **封面页与目录页不设页眉页码**；页眉从正文第一章开始
- 页眉文字用宋体/仿宋小五号，下加细横线

**3. 页脚与页码**

- 页脚居中页码，格式 `第 X 页 共 Y 页` 或纯数字；正文从第 1 页起编
- 页码字体字号同页眉

**4. 正文排版**

- 标题层级：章标题（第X章）三号黑体居中 → 节标题（X.1）四号黑体 → 小节（X.1.1）小四黑体 → 功能条目标题五号黑体
- 正文：宋体小四，1.5 倍行距，首行缩进 2 字符
- 表格：表头加底纹，五号宋体
- 每个功能配界面截图时，图下方居中标注图号图名（如"图 7-7-1 标记缺考界面"），图号按"章-节-序号"编号，全文连续

**5. 目录**

- 自动目录，含三级标题（章 / 节 / 小节），右侧带页码，点线连接
- 目录单独成页，置于封面之后、正文之前

---

### 阶段 3：收尾部分

1. **FAQ**：收集该系统中高频问题，按问题类型分类（登录类 / 操作类 / 数据类 / 异常类），每条 = 问题 + 现象 + 解决方案。
2. **附录**：快捷键表、错误提示信息对照表（错误信息 → 含义 → 处理方法）。
3. **技术支持**：联系方式（电话 / 邮箱 / 在线渠道）放在手册最后——鼓励用户先自助排查，再寻求帮助。
4. **全文一致性自检**：
   - [ ] 功能清单 100% 覆盖，无遗漏模块
   - [ ] 所有功能命名与系统界面实际名称一致
   - [ ] 术语、按钮名称、菜单路径全文统一
   - [ ] 每个高风险操作都有 ⚠️ 警告
   - [ ] 每个模块都有概述页
   - [ ] 操作步骤均为祈使句、含预期结果
   - [ ] 封面四要素齐全：文档标题（含版本号）、公司 Logo、公司名称、编写日期
   - [ ] 页眉从正文起，封面/目录页无页眉页码
   - [ ] 目录为自动生成、含页码、三级标题
   - [ ] 图片按"图 章-节-序号"编号并附图名

---

## 语言风格规范

- 使用第二人称"您"，保持专业礼貌。
- 操作步骤用祈使句："点击「确认」按钮"，而非"您可以点击确认按钮"。
- 避免"简单""只需"等可能暗示用户能力的词汇。
- 段落宜短（2–4 行），多用编号列表和表格，避免大段文字墙。
- 数据对比、参数说明一律用表格，不用文字罗列。

## 输出

默认输出为 Markdown 单文件（便于转 Word/PDF）。若用户要求 Word，使用 docx 相关工具转换，并严格执行"阶段 2.5 版式与排版规范"：封面四要素（标题含版本号、Logo、公司名、日期）、正文页眉页脚、自动目录、图号编号。最终交付时附一段简短的"使用说明"：本手册的结构逻辑和查阅建议。
